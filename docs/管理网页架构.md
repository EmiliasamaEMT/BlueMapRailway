# 管理网页架构

## 目标

管理网页保持“插件或模组单个 JAR 即可部署”的方式，不要求服务器安装 Node.js。开发阶段使用 ES Modules 拆分代码，浏览器直接加载 JAR 中的静态模块。

Paper 与 Fabric 共享页面、样式和 JavaScript，只保留各自不同的内置底图与服务端实现。

本文按当前 `0.2.1` 实现描述。旧版基线中的“保存后必然全量重扫”已不再适用于线路、站点、裁切和隐藏规则；显式重扫、配置 reload 和世界事件仍有各自的扫描路径。

## 目录

```text
core/src/main/resources/web/
  index.html
  style.css
  assets/
    app.mjs
    api.mjs
    store.mjs
    geometry.mjs
    viewport.mjs
    spatial-index.mjs
    map-view.mjs
    ui.mjs

paper/src/main/resources/web/
  default-background.png

fabric/src/main/resources/web/
  fabric-default-background.png
```

`paper` 和 `fabric` 的 JAR 任务已经包含 `core` 输出，因此共享网页会随两个产物一起打包。

## 模块职责

- `app.mjs`：应用编排、管理工作流、事件绑定和运行状态轮询。
- `api.mjs`：唯一 HTTP 客户端，统一 Token、JSON、网络错误和接口方法。
- `store.mjs`：唯一页面状态源，保存模式、世界、选择、编辑草稿、图层和过滤条件。
- `geometry.mjs`：X/Z 平面的范围、相交和距离算法。
- `viewport.mjs`：世界坐标与屏幕坐标转换、缩放、平移和适应范围。
- `spatial-index.mjs`：铁路折线的网格空间索引，避免每次点击遍历全部线路。
- `map-view.mjs`：Canvas 底图与铁路绘制、SVG 编辑覆盖层和线路命中检测。
- `ui.mjs`：标签页、对象列表、属性编辑器、运行状态、通知和确认窗口。

## 渲染结构

```text
map-stage
  background-canvas  底图、白色遮罩、坐标网格
  rail-canvas        可见铁路折线
  edit-overlay SVG   站点、裁切范围、选择高亮、框选草稿
```

选择 component 时只更新 SVG 选择层，不重建底图 Canvas，因此不会再出现点击线路时底图闪烁。铁路 Canvas 按颜色与线宽组合批量绘制，线宽直接使用后端返回的 route 或全局配置值，并通过空间索引完成点击和框选命中。

## 页面状态

页面状态只保存在 `store` 中：

- 当前浏览/管理模式和会话 Token。
- 当前世界、视口、工具和标签页。
- 选中的 component。
- route、station、mask 编辑草稿和未保存标记。
- 图层开关、透明度、搜索与筛选条件。
- 扫描和 BlueMap 渲染状态。

底图图层设置和编辑偏好写入 `localStorage`。管理 Token 可以记住用于下次登录预填，但页面刷新后仍默认以浏览模式请求公开状态。

## API

现有修改接口保持兼容。新增：

```text
GET /api/runtime
```

返回轻量运行状态：

```json
{
  "ok": true,
  "runtime": {
    "phase": "scanning",
    "scannedChunks": 120,
    "remainingChunks": 42,
    "pendingChunks": 8,
    "cachedChunks": 4096,
    "cachedRails": 18320,
    "lastScanCompletedAt": 0,
    "lastRenderCompletedAt": 0,
    "dataRevision": "instance-uuid:12",
    "timings": {
      "collectionMs": 0.0,
      "maxBatchMs": 0.0,
      "cacheMergeMs": 0.0,
      "graphMs": 0.0,
      "rulesMs": 0.0,
      "renderMs": 0.0
    }
  }
}
```

`phase` 可为：

- `waiting`：等待 BlueMap。
- `debounce`：等待扫描防抖或队列调度。
- `scanning`：正在分批扫描区块。
- `rendering`：扫描已完成，等待刷新 BlueMap 图层。
- `ready`：最近结果已更新。

前端每 3 秒轮询 `/api/runtime`。优先比较已加载数据与运行状态的 `dataRevision`，变化时重新请求完整 `/api/state`；旧服务端仍使用 `lastRenderCompletedAt`，避免大量线路时频繁传输完整 JSON。

线路、站点、裁切和隐藏规则保存/删除会持久化配置、从最近一次 base 结果重新应用规则并排队 marker 渲染，不会因此重新采集整个世界。`POST /api/rescan`、启动时首扫、配置 reload 和受影响区块事件仍可创建扫描任务。

## 测试结构

```text
web-tests/
  unit/          几何、空间索引、store、viewport
  browser/       模拟服务端和 Playwright 回归脚本
  fixtures/      固定线路、站点和规则数据
  performance/   10 万线路空间索引基准
```

测试命令准备如下，生产构建不依赖 Node.js：

```powershell
cd web-tests
npm ci
npm run test:unit
npm run test:browser -- --workers=1
npm run test:performance
```

当前门禁已验证：21 项前端单元测试、22 个桌面/窄屏 Playwright 场景通过并以退出码 0 返回；浏览器测试由 global setup/teardown 管理 mock server。`test:performance` 仍只是空间索引基准，不能据此宣布服务器性能通过。

## 0.2.0 更新与计时契约

`dataRevision` 是不透明字符串，实例重建时前缀变化。只有成功加载 `/api/state` 后才认可其中的版本；失败或返回旧版本时下次轮询继续重试。元数据在首次扫描前也可更新，此时不代表已有铁路几何结果。

`runtime.timings` 单位为浮点毫秒：

- `collectionMs`：当前/最近一次扫描的批次执行累计时间，不含 tick 间等待。
- `maxBatchMs`：同一次扫描内最长批次时间。
- `cacheMergeMs`：扫描准备阶段合并缓存节点的耗时。
- `graphMs`：最近一次该扫描器建图耗时。
- `rulesMs`：最近一次规则应用耗时，包含现有自动延续持久化开销。
- `renderMs`：最近一次成功 BlueMap 渲染调用耗时，不含 SVG。

扫描计时在开始新扫描时归零；尚无扫描器时省略四个扫描字段。字段是最近观测值，不是同一事务的性能追踪，也不表示端到端更新延迟。SVG 暂不维护，默认关闭。

## 0.2.1 网页重写

视觉样式重写为浅色绿色工作台：顶部世界/登录状态、左侧地图工具、右侧对象列表与属性编辑器。手机默认显示地图，可展开/收起面板；新增显式缩放按钮。API 路径、字段和既有表单标识继续兼容，CRUD 业务入口保留。

地图内部使用累积失效标记和单个 requestAnimationFrame，平移只更新 Canvas 与 SVG viewBox，不重复创建站点、裁切和选择节点。铁路按视口和最大线宽边距查询，绘制组保持全局样式顺序；点击查询先过滤世界和显隐，再选最近线路。相同距离保留后出现的源数据线优先，未改为按视觉堆叠选线。

空间索引重写：缓存每条线的 bounds，最多为一条线枚举 256 个格子；超大线路进入独立候选列表，超大视口扫描缓存 bounds。避免超长对角线或全图查询分配巨量格子。输入几何在 setData/rebuild 之间不可原地修改。

线路列表每页最多 60 个对象，搜索改变后回到第一页。站点与规则列表仍使用常规列表。请求响应通过递增代数及 token 校验丢弃过期结果；轮询不重入，页面隐藏时暂停请求，关闭页面取消渲染帧和定时器。底图更换不会被旧图片加载回调覆盖。

新增站点/裁切坐标必填校验、保存期间防重复提交、运行阶段耗时展示。轮询和手动刷新保留未保存草稿。测试和剩余边界见[网页重写执行记录](执行记录/管理网页重写-2026-09-19.md)。
