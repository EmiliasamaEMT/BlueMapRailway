配套：[阶段路线图](0.2系列优化与重构路线图.md)。本文是操作流程，不是现成测试结果，也不是服务器部署或发布授权。

1. 阅读当前会话及磁盘上的适用 AGENTS 指令。

3. 查看 Git 状态和该阶段涉及的少量文件；不要先遍历全部历史对话或源代码树。

5. 在开始改动前说明本轮范围及验收条件。文档中的未来阶段不等于用户一次授权全部实施。

本机实际 Git 仓库：`C:\github\bluemap_railway\BlueMapRailway`，外层目录不是可直接使用的 Git 仓库。

```powershell
Set-Location C:\github\bluemap_railway\BlueMapRailway
```

## 3. 构建与自动化命令

### 3.1 Java

当前工具链：Gradle Wrapper 9.4.0；主构建使用 Java 25，core 自身配置为 Java 21。版本依赖以 `gradle.properties` 为准，不因最新版本可用就升级。

```powershell
java -version
.\gradlew.bat --version
.\gradlew.bat :core:test :paper:build :fabric:build
```

本机缓存齐全时可加 `--offline`。缓存缺失导致的离线失败不是源码错误；确认依赖缺失后再按环境权限正常解析依赖。无需执行 `clean`。

需要显式开发版本时，选择当前尚未发布的 `0.2.x`，例如：

```powershell
.\gradlew.bat :paper:build :fabric:build "-PpluginVersion=0.2.1-dev"
```

这是示例版本，不代表应覆盖当前默认 0.2.0 或跳过其验收。

产物：`paper/build/libs/BlueMapRailway-<version>.jar`、`fabric/build/libs/BlueMapRailway-fabric-<version>.jar`。测试应记录实际文件名，勿用通配符复制多个历史 JAR 到插件目录。

已知本机故障：Fabric Loom 曾因用户临时目录 `intermediary-*.jar` 的 `AccessDeniedException` 失败；在允许访问用户缓存/临时文件后构建成功。先看异常根因，必要时使用工具的权限升级机制，不能为此批量删除 Gradle/Loom 缓存。

如果日志显示 `remapJar` 阶段 daemon 因 heap 不足断开，先保持 `--max-workers=1`，把构建 JVM 调到已验证的范围：

```powershell
.\gradlew.bat --no-daemon :paper:build :fabric:build --max-workers=1 `
  "-PpluginVersion=0.2.0" `
  "-Dorg.gradle.jvmargs=-Xms128m -Xmx512m -XX:MaxMetaspaceSize=384m"
```

本机本轮还需要提升权限让 Loom 查询临时映射锁；先使用权限升级重试，不删除锁文件或整个缓存目录。

### 3.3 Windows 浏览器运行器与退出清理

当前 `playwright.config.mjs` 通过 `browser/global-setup.mjs` 在同一 Playwright 生命周期中启动并关闭 mock server；默认命令已验证可以退出码 0 返回。推荐使用：

```powershell

```

若失败，先确认断言是否完成、18765 端口由谁占用，以及是否只剩本轮启动的 mock server。只处理本任务启动且已记录的进程；不要停止全部 Node/Java 进程，也不要用临时配置掩盖默认命令的问题。必要时可在 `web-tests` 目录单独运行 `node browser/mock-server.mjs` 做定位，完成后必须在同一会话停止它。

浏览器测试结束后复核 18765 端口和本轮进程；临时报告留在已忽略目录，不批量删除测试结果。

## 4. 真实测试环境操作

本机有 `C:\github\bluemap_railway\test_service`（Paper）与 `C:\github\bluemap_railway\fabric_test_service`（Fabric）。目录存在不代表服务器正在运行，也不代表本轮有权限修改其内容；它们可能位于当前可写范围之外。

部署前：

1. 核对用户授权、当前进程、实际插件/mod 目录、启动脚本和端口。只读确认必要配置，不把 token、RCON 密码打印到日志或提交文档。
2. 记录当前插件版本、世界、BlueMap 版本及待替换 JAR 的明确路径。
3. 使用既有备份能力或复制明确的数据文件，保留 `config.yml / routes.yml / stations.yml / edits.yml` 和必要缓存；世界对照测试使用可恢复副本。
4. 停服后替换唯一目标 JAR；旧文件逐个移动到备份目录，避免同目录加载两版本。移动前验证绝对路径在指定测试目录内。
5. 检查测试配置 `export.svg.enabled: false`。不改生产配置来满足测试。
6. 按已检查的脚本启动；后台启动使用隐藏窗口，除非用户要求可见控制台。
7. 通过日志和 API 验证实际运行 0.2.x，不能只看磁盘 JAR 名称。

### 4.1 测试服生命周期与内存纪律

真实测试服是本机高占用资源，必须按“启动、验证、关闭、确认”一个闭环执行。**测试完成后不能把停服留给下一轮 agent，也不能因为命令失败就跳过清理。** Paper 和 Fabric 使用相同的端口，默认只允许启动一个测试服。

启动前先确认没有遗留监听或 Java 进程：

```powershell
$ports = @(25565, 8100, 8766, 25575)
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
  Where-Object { $ports -contains $_.LocalPort } |
  Select-Object LocalAddress,LocalPort,OwningProcess
Get-Process java,javaw,gradle -ErrorAction SilentlyContinue |
  Select-Object Id,ProcessName,WS,StartTime,Path
```

先完成构建，再启动测试服；不要让 Fabric Loom/Gradle remap 与 Minecraft 服务器同时争用内存。Paper `start.ps1` 和 `start-background.ps1` 当前默认申请 `-Xms1G -Xmx2G`，Fabric `start.ps1` 没有显式堆上限；机器内存紧张时不要直接使用这些默认启动方式，应使用本机可承受的临时堆上限，并在记录中写明实际 JVM 参数。小型 smoke test 可从 `-Xms256m -Xmx1G` 起步，真实大世界测试需根据数据规模单独提高。测试服运行期间不要同时启动 Paper 和 Fabric。

启动后记录服务 PID、监听端口和 Java 工作集；只做必要的 API/日志回归，不为了等待而长时间保持服务器运行。每个测试流程都要安排关闭步骤：

```powershell
$serviceRoot = 'C:\github\bluemap_railway\test_service' # 或 fabric_test_service
$ports = @(25565, 8100, 8766, 25575)
try {
  # 在另一个已记录的会话启动并验证测试服
  # 执行本轮 API/浏览器/服务器回归
}
finally {
  & (Join-Path $serviceRoot 'stop.ps1')
  Start-Sleep -Seconds 3
  Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $ports -contains $_.LocalPort } |
    Select-Object LocalAddress,LocalPort,OwningProcess
}
```

Paper/Fabric 的 `stop.ps1` 会优先使用 RCON；停服后必须确认 25565、8100、8766、25575 均无监听。若脚本报告无监听但仍有 Java 进程，只能根据本轮记录的 PID、启动时间和命令行逐个核对；禁止用“结束全部 Java/Gradle 进程”的方式清理。若内存压力已经影响桌面，先执行对应 `stop.ps1`，再检查进程和端口，最后才继续其他命令。

结束本轮前必须在交接记录写明：测试服已停止、端口检查结果、是否仍有本轮启动的 Java/Gradle 进程、实际堆参数和日志路径。未通过关闭确认前，不得开始下一平台测试或结束任务。

以下地址仅是历史 Paper 默认示例，先核对实际端口。公开 API 无需把管理 token 放入命令：

```powershell
$adminBase = 'http://127.0.0.1:8766'
$beforeRuntime = (Invoke-RestMethod "$adminBase/api/runtime").runtime
$beforeRuntime | Select-Object phase,dataRevision,lastScanCompletedAt,lastRenderCompletedAt,pendingChunks,timings
$webState = Invoke-RestMethod "$adminBase/api/state"
@{ routes = @($webState.routes).Count; components = @($webState.components).Count; lines = @($webState.lines).Count }
```

写操作优先通过管理网页完成。程序化测试按 `web/assets/api.mjs` 的实际请求体和服务器 handler 构造，用测试 token 的请求头；不得硬编码真实 token 或放入报告。

## 5. P0 管理操作回归矩阵

前置说明：P0 已完成，以下矩阵作为后续 0.2.x 回归补充模板。已由执行记录覆盖的案例不要为了“重新开始”重复启动测试服。

前置：完成初始扫描，确认服务器处于可观察的稳定状态。打开两个浏览器会话，A 管理、B 浏览。除测试目标外避免走动加载区块/铺轨，避免误把世界事件扫描算作管理操作导致的扫描。

| 编号 | 操作 | 预期与证据 |
|---|---|---|
| M01 | 改线路名称、颜色、线宽 | API/网页正确；revision 改变；没有因此新增扫描；B 在成功轮询后更新 |
| M02 | 分配/取消 route 归属 | 归属结果正确；无额外采集；已有自动延续规则不得被悄悄改变 |
| M03 | 创建/修改/删除站点 | 范围及图层正确；无需重新采集轨道 |
| M04 | 添加隐藏规则再删除 | 隐藏生效；删除后从 base 恢复；节点缓存不被裁掉 |
| M05 | 添加裁切范围再删除 | 几何裁切正确且不累积；删除后恢复原折线 |
| M06 | 等待渲染时连续保存两次 | pending 结果替换为最新；最终 marker 为第二次数据 |
| M07 | 扫描进行中保存规则 | 扫描完成后仍使用有效的最新规则，不被旧派生结果覆盖 |
| M08 | 首次扫描前保存可保存的元数据 | 无异常；API 版本可更新但不伪造几何；首次扫描结果应用规则 |
| M09 | B 的一次 state 请求失败 | 未认可新版本；下次轮询重试并成功更新 |
| M10 | 重启服务后 B 保持打开 | UUID 变化可触发刷新；不依赖计数必须比旧实例大 |
| M11 | 手动 rescan、配置 reload、放置/拆除轨道 | 原有必要扫描路径仍有效；被拆轨道最终消失 |
| M12 | 公开与管理模式读取 | 隐藏/裁切管理字段权限与基线一致，不能串用缓存 |

对 M01–M05 至少记录操作前后 `lastScanCompletedAt`、`dataRevision`、扫描队列和日志。仅时间戳未变不足以证明没有排队；观察范围需覆盖当前配置的扫描防抖窗口。

对 M06 记录 API 与 marker 的最终结果，`lastRenderCompletedAt` 不等于浏览器已收到 BlueMap 更新。网页自己的数据刷新一般受 3 秒轮询影响，不承诺严格 3 秒上限。

每个案例在 Paper/Fabric 单独记录结果。两平台使用不同世界 ID 时先明确映射，不直接比较完整 JSON 字节。

## 6. 性能采样方法与解释

每组记录：硬件/JVM、平台版本、插件版本、启用世界、缓存区块数、轨道节点数、component/line 数、相关防抖与扫描配置、样本时段和操作次数。

建议数据集包含：小型语义夹具、真实铁路世界副本、大量长折线与岔道数据。不要只用十万个两点短线代表真实大世界。

同一环境重复相同操作，分开记录首次加载与预热后结果。不要用单次最好结果代表收益。

| 指标 | 0.2.0 含义/限制 |
|---|---|
| collectionMs | 本次扫描批次累计执行时间，不含 tick 间等待；不是端到端时长 |
| maxBatchMs | 本次扫描最长采集批次；不包含整个建图/规则/渲染峰值 |
| cacheMergeMs | 开始扫描合并缓存节点的时间 |
| graphMs | 当前扫描器最近一次建图；新扫描重置后完成前可为 0 |
| rulesMs | 最近一次规则处理，可能包含自动延续写文件 |
| renderMs | 最近一次成功 marker 渲染调用；不包含 SVG，也不是 BlueMap 浏览器绘制时间 |
| dataRevision | 不透明数据版本，不能拿来相减计算耗时或排序不同实例 |

API 只保留最近观测，轮询可能漏掉短阶段。需要精确 p95/异常时序时先补限定范围的采样或使用服务器 profiler，不能从几个 API 样本推导全量 p95。

用 profiler 区分世界读取、建图、规则、序列化、marker 提交及其他插件。此前历史 sparkprofile 对话没有可靠的归因结论，不能引用“已经证明某模块最慢”。

建议结果表：

```text
场景 | 平台/版本 | 数据规模 | 操作次数 | 主线程最长片段 | MSPT p50/p95
     | 采集/建图/规则/渲染观测 | API更新延迟 | marker更新延迟 | 队列峰值 | 结论
```

无测量的单元格填“未测”，不填 0。先定位主要成本再选择 P3/P5 优化项。

## 7. 后端测试实施指南

当前 `core` 已有可依赖的 JUnit 5 Java 回归测试套件；P1 后续应继续扩充语义夹具，并确保 `:core:test` 实际运行测试而非退回 `NO-SOURCE`。

当前 `core` 测试配置已经可运行。优先在仓库根目录执行：

```powershell
$env:JAVA_HOME="C:\Program Files\Java\jdk-25"
.\gradlew.bat :core:test --max-workers=1
```

如果根工程因为 Fabric Loom 临时映射锁或本机内存不足无法进入 `core:test`，使用仓库内的隔离 settings（不改产品工程结构）：

```powershell
Set-Location build/core-test-project
$env:JAVA_HOME="C:\Program Files\Java\jdk-25"
& "..\..\gradlew.bat" --no-daemon :core:test --max-workers=1 `
  "-Dorg.gradle.jvmargs=-Xms64m -Xmx256m -XX:+UseSerialGC -XX:MaxMetaspaceSize=256m"
```

确认输出包含 `:core:test` 和 `BUILD SUCCESSFUL`，并检查 `core/build/test-results/test/*.xml` 的 `failures`、`errors` 均为 0。不要只看 `compileTestJava` 成功；缺少 `junit-platform-launcher` 时源码会编译但测试执行器无法启动。

固定夹具最少覆盖：

- 平直线、普通/动力轨交替、坡道、环线、T 型岔点、跨 chunk 连接、不同世界同坐标。
- 原始 base → 隐藏/裁切 → 删除规则 → 恢复；同一规则重复应用不改变结果。
- route 精确匹配、锚点自动延续、多个 route 冲突、延长导致 component ID 变化。
- 新连接合并组件、删除连接拆分组件、渲染合并保留来源信息。
- P2/P3 引入后使用可控调度器验证：两次保存、旧任务晚完成、reload/stop、失败、队列合并。

比较时明确排序规范，保留有语义的顺序；浮点几何容差必须说明来源。不要只断言输出数量或将新实现生成结果直接存成唯一真值。

纯规则无需真实世界对象；平台桥接与真实线程边界仍需平台测试，不能用纯单元测试替代。

## 8. 架构咨询与工作拆分

沿用 AGENTS 的 Luna 主执行 / Astra 有界咨询政策。普通文档、构建、定位、已决定方案实现不需要咨询。以下变化触发咨询：共享模块接口、状态机、并发、生命周期、所有权，或两次聚焦实现/调试仍失败等。

咨询内容限于：决策问题、触发条件、已核实事实、候选方案、约束、具体文件/符号、需要回答的事项。默认不传整段历史；不把 Astra 当实现者。

已有方向：先分类变更与基线，纯规则共享后再异步；不机械合并两套 Service；版本校验覆盖真实副作用；增量图必须处理合并/拆分。它们是设计约束，不是当前代码已经完成的能力。

## 9. 每轮交接记录模板

实际执行一个阶段后再创建记录，例如 `docs/执行记录/P0-YYYY-MM-DD.md`。不预建一堆空文件。

```markdown
# Pn 执行记录

```

## 10. 完成与回退标准

- 只完成用户授权的阶段；必要调用方、测试与文档一并更新。
- 运行与改动匹配的最小验证；通过后不为额外信心重复全套测试。
- 文档改动只校验链接、命令和事实，不机械跑双端构建。
